### 1. CREATE INDEX on orders (2.0M rows, 380 MB) without CONCURRENTLY blocks writes until the build finishes

The statement `CREATE INDEX ix_orders_status ON orders (status)` builds an index on public.orders (2.0M rows, 380 MB) without `CONCURRENTLY`. Standard `CREATE INDEX` in PostgreSQL acquires a `SHARE` lock on the table for the entire index build, blocking all `INSERT`, `UPDATE` and `DELETE` statements.

**Fix:** Use `CREATE INDEX CONCURRENTLY` (outside a transaction block) so writes continue while the index builds.

```sql
CREATE INDEX CONCURRENTLY ix_orders_status ON orders (status);
```
